# 개인 보드 + 그룹 대시보드

> 현재 상태: GitHub 비공개 저장소에서 설계와 검증을 관리합니다. 실제 웹서비스 런타임은 GitHub와 분리해 배포합니다.

개인은 자신의 업무와 RAG 자료를 관리하고, 필요한 항목만 그룹의 **업무·공지·질문·마감·일정**으로 발행합니다.

- Google Sheets: 공용 데이터베이스이자 관리자용 원장
- Google Drive: 공지, 업무, 일정에 붙이는 파일 저장소
- Google Apps Script: 웹 화면, 데이터 API, 오전 9시 및 3시간 주기 갱신
- 브라우저: 팀원이 쓰는 화면. Slack과 Teams는 연결하지 않습니다.
- 개인 Work-board: 로컬 상태에서 **공유할 요약만** 고르는 개인 신호 입력원입니다.

## 설치 순서

1. Google Sheets에서 새 스프레드시트를 만들고 이름을 `팀 업무 보드`로 정합니다.
2. 상단 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
3. `apps-script/Code.gs` 내용을 기본 `Code.gs`에 붙여넣습니다.
4. Apps Script 편집기에서 HTML 파일 `Index`를 새로 만들고, 아래 `apps-script/Index.html` 내용을 붙여넣습니다.
5. `appsscript.json`을 매니페스트 파일에 반영합니다.
6. Apps Script에서 `ensureBoard_`를 한 번 실행해 권한을 승인합니다. 시트 탭과 샘플 데이터가 생성됩니다.
7. `installTriggers`를 한 번 실행합니다. 오전 9시 및 3시간 주기 갱신이 설정됩니다.
8. **배포 → 새 배포 → 웹 앱**에서 실행 주체는 배포자, 접근 범위는 팀 도메인 사용자로 지정합니다. 배포 URL을 팀에 보냅니다.

## 데이터 탭 계약

| 탭 | 하는 일 | 기록 주체 |
| --- | --- | --- |
| `Members` | 팀원, 역할, 사용 여부 | 관리자 |
| `Tasks` | 업무, 담당자, 마감일, 상태, Drive 링크 | 팀원 |
| `Announcements` | 공지와 첨부 링크 | 관리자/리드 |
| `ReadReceipts` | 공지를 본 사람과 시각 | 자동 |
| `Questions` | 공지별 질문 | 팀원 |
| `Activity` | 등록·확인·완료·갱신 이력 | 자동 |
| `Schedule` | 일정과 관련 파일 | 팀원 |
| `Promotions` | 개인 신호에서 골라 팀에 발행하기 전의 요약 대기함 | 사용자/자동 |
| `SyncLedger` | 대기 항목이 어느 팀 기록으로 발행됐는지 남기는 추적 원장 | 자동 |
| `Settings` | 마지막 갱신과 요약 상태 | 자동 |

## 운영 기준

- 앱은 **도메인 사용자**에게만 배포합니다. 웹에 공개하면 이름을 선택한 사용자가 기록을 남길 수 있어 팀 기록의 신뢰도가 떨어집니다.
- Apps Script의 시간 기반 트리거는 정확히 09:00:00에 실행된다고 보장되지 않습니다. 오전 9시 전후에 실행되어 시트의 요약 상태를 갱신합니다.
- 외부 푸시는 넣지 않았습니다. 페이지를 열어 둔 사람은 브라우저 알림을 허용하면 새 공지와 마감일을 볼 수 있습니다.
- **개인 신호 → 공유 대기함 → 팀 반영** 순서를 지킵니다. 개인 Work-board의 원문 데이터(메일, 메신저, 앱 사용 기록 등)는 이 앱이나 Google Sheets로 자동 복사하지 않습니다.
- 로컬 `Index.html`은 브라우저 `localStorage`에서 독립 실행됩니다. 팀 시트로 실제 발행하려면 Apps Script 웹 앱 URL에서 열어야 합니다.
